# Folder structure

Feature-based: code for one feature lives together.

```
design-tokens/            # generated by `npm run tokens`, do not edit
design-tokens-build/      # generated theme CSS and types, do not edit
designsystemet.config.json
src/
  main.tsx                # entry point, renders app/App
  app/                    # App.tsx (providers), routes.tsx, global.css
    layout/               # AppLayout, AppHeader (skip link, header, navigation, main)
    errors/               # error and not-found pages
    mock-tools/           # mock-only test environment bar (Reset mock data, user switcher)
  features/
    cases/                # F-001, F-002
      pages/              # route pages, exported through index.ts
      components/
      hooks/
      api.ts
      types.ts
    overview/             # F-003 case overview + filters
    auth/                 # current user, roles, permissions.ts (F-004)
    follow-up/            # F-010, F-011
    notifications/        # F-012
    admin/                # users (F-004), global audit log (F-005)
  shared/
    components/           # reusable wrappers around Designsystemet, e.g. Page
    api/                  # apiRequest: the one way to call the API
    utils/
  mocks/                  # MSW: browser.ts, node.ts (tests), handlers/, db.ts (localStorage), seed/
  test/                   # Vitest setup and shared test helpers (renderRoute)
tests/e2e/                # Playwright specs; fixtures.ts has the console and axe checks
public/mockServiceWorker.js  # generated by MSW, do not edit
```

Rules
- A feature may import from `shared/` and from another feature's `index.ts` only, using the `@/` alias.
  ESLint (`no-restricted-imports`) blocks deep imports like `@/features/auth/permissions`.
- Tests sit next to the file: `CaseForm.tsx` + `CaseForm.test.tsx`.
